# Offline OCR table recognition

The implementation localises table regions with a hash-pinned PP-Structure PicoDet model, then decodes each crop with SLANet-plus. It reuses the admitted RapidOCR boxes, text and confidence; it never reruns OCR for a table. Ruled-grid boundaries refine loose crops without trimming empty cells. Aligned multi-column rows may propose borderless crops, which still require a valid structure-model result.

Only OCR regions actually matched into a valid table are consumed. The first consumed OCR index anchors each table in reading order. Unmatched regions, captions, prose and failed crops remain plain text. A successful table elsewhere does not discard a failed table. HTML-like OCR strings are escaped before structure assembly; Markdown cells escape literal pipes and angle brackets. Merged cells use the existing fill/empty/marker semantics. This is best-effort recognition, not a guarantee of exact geometry for every scan or a formula-recognition feature.

`ocr.recognize_tables` ships as true. The GUI has a separate table checkbox and an Export preference; turning OCR off disables the checkbox without changing its value. Unavailable models disable the control with an explanation. CLI `--recognize-tables` / `--no-recognize-tables` requires `--ocr`. Machine capabilities expose optional boolean `recognize_tables`; omission uses the request's frozen configuration. An explicit request value wins over configuration. No schema default is injected that could hide a configured false value.

The same policy reaches image/TIFF, physical-page PDF/OFD/XPS, embedded DOCX/XLSX/PPTX and markup images, and Gongwen's embedded images. Cancelling a table call propagates the request cancellation at model and crop boundaries. Each inference call itself is synchronous; it cannot be interrupted mid-ONNX invocation.

Model discovery is local and lazy. Missing or corrupt selected models produce `OCR-TABLE-UNAVAILABLE` and preserve plain OCR. Other partial or full structure failures produce `OCR-TABLE-FALLBACK`. `OCR-BEST-EFFORT.<status>` carries blank or operational OCR status through GUI and Machine without parsing English messages. Successful OCR emits the informational `OCR-QUALITY-NOTICE`, deduplicated per runtime task and per displayed GUI operation.

Both models are SHA-256 pinned in runtime and packaging contracts. The build fetches verified inputs before compilation; runtime performs no model downloads. Source tests cover region accounting, partial fallback, literal text, merge policy, disabled/missing/corrupt models, cancellation, configuration precedence, GUI control state and diagnostic delivery. The checked `tests/fixtures/files/ocr_tables/mixed-tables.png` corpus supports actual-model verification with `verify_packaged_cli.py --table-smoke`. Actual packaged and native-host results are separate acceptance evidence; source tests do not prove those boundaries.
