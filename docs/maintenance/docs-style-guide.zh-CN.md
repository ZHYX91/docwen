# 文档规范

[English](docs-style-guide.md)

## 位置与命名

- 根目录保留入口：`README.md`、`CONTRIBUTING.md`、`SECURITY.md`、`CHANGELOG.md`，以及既有许可与声明文件。开发步骤只在 `docs/development.md` 及其语言版本维护。
- `docs/README.md` 索引产品指南、开发、架构和规格。README 译本放 `docs/i18n/README.<locale>.md`，任务指南放 `docs/guides/`，截图放 `docs/assets/screenshots/`。
- 公开产品 README 保留 `# DocWen` 和统一原生语言导航，使用 `·` 分隔及 GitHub `blob/main` 绝对链接；保留既有语言代码。
- 普通文件使用小写英文和连字符。保留 `README.md` 等惯用名称及既有许可证文件名。日期用于历史记录，不用于长期指南。
- 完整语言版本分文件：英文 `name.md`，中文 `name.zh-CN.md`。专业术语、界面原文和样例可包含多种语言；不要求为所有工程参考新增翻译。
- 正式技术决策随源码保存在 `docs/architecture/decisions/`。本机计划、迁移回执、运行日志和历史验收记录属于维护工作区。普通 clone 必须自带使用、构建、测试与发布所需说明。

## 写法与维护

- 写清当前行为、归属和限制，明确区分计划中的能力。当前指南不写阶段编号、完成流水账或测试数量快照，也不依赖私有计划和历史验收记录。
- 每个易变事实只有一个主要来源，其他位置使用链接。
- 用户指南围绕任务，实施细节放到对应技术参考。
- 维护中的语言对同步更新，保留语言导航和实际限制；源码检查不能写成打包或实体验收通过。
- 移动文档同步修改相对链接、仓库 URL、打包入口及检查器。保留许可证原文和历史记录原始字节。

修改后检查本地链接、原生文档门禁及 `git diff --check`。
