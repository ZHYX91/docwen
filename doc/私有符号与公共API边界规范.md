---
title: 私有符号与公共API边界规范
---

## 目的

- 明确哪些符号属于实现细节（不应被外部依赖），哪些属于公共 API（允许被 tests/tools 依赖）
- 降低 IDE/Pyright 的告警噪音，避免真正的问题被淹没
- 保持重构自由度：实现层可随时调整，不被测试/工具“绑死”

## 术语

- **私有符号**：以 `_` 开头的模块级函数/变量/类，或第三方库的 protected/private 成员（如 `obj._element`）
- **公共 API**：稳定、可被外部依赖的入口；本项目中指“明确导出的规则级/行为级入口”
- **过渡入口（wrapper）**：为消除私有符号调用而临时新增的公开转发函数，不承诺稳定

## 硬规则（必须遵守）

### 1) `src/`：绝对禁止跨模块使用私有符号

- 禁止：
  - `from x import _foo`
  - `import x; x._foo(...)`
  - 访问第三方库的 protected/private 成员（例如 `obj._element`），除非按“第三方例外规则”处理
- 合法出口：
  - 将能力提升为公共 API（新增非下划线入口），再由外部调用

### 2) `tests/` 与 `tools/`：默认禁止使用私有符号

- 默认禁止同上（import `_foo` / 调用 `module._foo` / 访问 `_member`）
- 合法出口：
  - 在 `src/` 中新增公共 API（非下划线），tests/tools 只依赖该公共 API

### 3) 无白名单，例外只能 `# type: ignore` 且必须注明原因

- 不允许维护“允许列表/白名单”
- 所有例外必须：
  - 使用 `# type: ignore[...]`（尽量写明具体规则名）
  - 紧跟一句原因说明（说明为什么无法封装或迁移）

## 第三方库 protected/private 成员的处理（python-docx 等）

### 规则

- 允许访问第三方库的 protected/private 成员，但必须同时满足：
  - **封装**：在本项目 `src/` 内提供 1 个统一封装函数/适配层
  - **注释**：在调用点保留必要的 `# type: ignore[...]`，并注明原因

### “超过 3 处同类调用必须封装”阈值

- 若同一类 protected/private 成员访问（例如 `Paragraph._element` / `Run._r`）在 `src/` 内出现超过 3 处：
  - 必须抽成封装函数（单点出口），其余地方统一调用封装函数
  - 目标是把风险（第三方升级断裂）集中在 1 个位置

## 公共 API 的定义与新增标准

当某段逻辑满足任一条件，应提升为公共 API（非下划线）：

- tests/tools 需要调用
- 属于“规则级纯函数”（parse/normalize/find/build），语义稳定、依赖少
- 属于“行为级入口”（convert/execute），外部需要以此调用模块能力

公共 API 应满足：

- 命名语义明确（动词开头）
- 输入输出稳定（避免暴露内部状态结构）
- 不要求调用方传入内部临时对象/内部路径等实现细节

## 过渡入口（wrapper）的定位

- 当前仓库中已经存在的一批 wrapper：**全部视为过渡解**
- 过渡入口不承诺稳定：后续允许迁移、收敛、甚至删除
- 对外承诺的稳定入口，应在后续按域建立集中入口层（例如 `api.py`），再逐步替换过渡入口

## ConfigManager 特别约束

- 当前 ConfigManager 上为测试暴露的一批方法：视为临时妥协，优先清理
- 目标方向：
  - tests 通过“公开业务语义接口”验证行为，不直接读写内部状态
  - 必要时通过 fixture/上下文注入隔离副作用，而不是开放内部重置接口

## 推荐的改造路径（当发现私有符号被外部依赖时）

1. 判定是否属于“规则级能力”或“行为级入口”
2. 在 `src/` 内新增公共 API（非下划线），并补单元测试
3. tests/tools 改为依赖公共 API
4. 保留原 `_xxx` 作为实现细节（或迁移到实现层模块），避免破坏内部结构
5. 如涉及第三方 protected/private 成员，按本规范封装并集中出口
